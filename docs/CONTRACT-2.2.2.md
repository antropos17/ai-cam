## Интент (ратифицирован человеком 2026-08-03)

BugCam обязан захватывать типичные сторонние сцены, а не только собранные из
примитивов. Блок добавляет **ровно два расширения захвата и ничего больше**;
всё остальное сохраняет текущие fail-closed исходы A2.

## Жёсткое ограничение v0.1 (заявляется в контракте явно)

**Gameplay-скрипты не выполняются в локальной PhysicsScene.** v0.1 захватывает
физическую сцену, не игровую логику: движение от MonoBehaviour/Animator/ввода в
симуляции не воспроизводится. Это границы охвата `SPEC.md` §13 («Not in v0.1:
… arbitrary gameplay code inside local PhysicsScene …; a slower Play-Mode replay
path for full MonoBehaviour scenes comes later»), а не дефект. Захваченная
сторонняя сцена честно отвечает на вопрос «как разойдётся её физика», и только
на него.

## Расширение 1 — статические MeshCollider (non-convex и convex)

Объект **без Rigidbody** с MeshCollider переходит из fail-closed в
**CapturedStatic** при выполнении ВСЕХ условий:

- `sharedMesh != null`;
- `convex` — **любое значение** (Адъюдикация 2026-08-04, вопрос №1: convex-статика
  захватывается наравне с non-convex — convex hull строго проще, статика не
  движется; фактический флаг фиксируется в меш-ссылке и входит в хэш);
- коллайдер enabled, не trigger; `sharedMaterial == null` (без изменений);
- без shear (текущая проверка `HasShear` без изменений; допуск смешанный:
  `1e-4 · max(1, |a|, |b|)` — относительный с абсолютным полом 1e-4);
- `cookingOptions == MeshColliderCookingOptions` по умолчанию Unity — иначе
  fail-closed (следует конвенции «нестандартная настройка ⇒ отказ» — это
  сводная формулировка контракта, не литерал кода; прецеденты в коде:
  «нестандартный damping (…) не воспроизводится харнессом»,
  «collisionDetectionMode отличен от Discrete — не поддерживается»);
- все компоненты `lossyScale` конечны и **строго положительны** — отрицательный
  масштаб (зеркалирование) ⇒ fail-closed с причиной (Адъюдикация 2026-08-04,
  вопрос №4: fail-closed БЕЗ эмпирического исследования — поведение
  зеркалированных convex hull в PhysX плохо предсказуемо, а продукт продаёт
  воспроизводимость);
- меш-ссылка разрешается (см. «Меш-ссылка»).

Статика никогда не движется ⇒ **охват детерминизма не меняется**: состояние
статики не входит в 14-float stride, в запись и в сравнение — как и сегодня.
Захватываются `position = transform.position`-эквивалент по текущей схеме
статики, `rotation`, полный `lossyScale` (см. «Поверхность изменений»), плюс
меш-ссылка. Ключи статики сохраняют текущую схему `#NN`-суффиксов; порядок и
нумерация stable ID не меняются.

## Расширение 2 — динамические Rigidbody с convex MeshCollider

Тело с Rigidbody и MeshCollider переходит из fail-closed в **CapturedDynamic**
при выполнении ВСЕХ условий:

- `sharedMesh != null` и `convex == true`. **`convex == false` на динамике
  остаётся fail-closed** (Unity/PhysX сами запрещают non-convex меш на
  не-кинематическом Rigidbody — отказ честно называет причину, см. таблицу);
- ровно один контактный коллайдер на теле (без изменений — compound остаётся
  отказом);
- ВСЕ существующие Rigidbody-проверки A2 без изменений: масса > 0 и конечна,
  `useGravity == true`, `constraints == None`, damping `0 / 0.05`, `Discrete`,
  авто-COM и авто-инерция (инерция считается PhysX по convex hull — поэтому
  требование авто-инерции сохраняется дословно), без Joint/ArticulationBody;
- `cookingOptions` дефолтные, `lossyScale` строго положительный, без shear,
  `sharedMaterial == null` — как в расширении 1;
- меш-ссылка разрешается.

Кинематика с MeshCollider замораживается в статику по текущему правилу A2
(с той же Animator-пропагацией предупреждения), но только если её меш проходит
условия расширения 1 (для static-заморозки достаточно правил статики);
иначе — fail-closed.

## Меш-ссылка (единый формат для обоих расширений)

Меш захватывается **по ссылке на ассет**, не по копии геометрии:

| Поле | Содержание |
|---|---|
| `assetGuid` | GUID ассета-источника (`AssetDatabase`) |
| `localFileId` | local file ID суб-ассета Mesh внутри источника (fbx может нести несколько мешей) |
| `meshName` | имя меша (диагностика/отчёт; не участвует в резолве) |
| `contentHash` | SHA-256 **по геометрии**, не по байтам файла (Адъюдикация 2026-08-04, вопрос №2 — см. ниже) |
| `convex` | флаг MeshCollider на момент захвата |

**contentHash (Адъюдикация 2026-08-04, вопрос №2):** хэш считается по
рантайм-геометрии, не по байтам файла ассета — байты файла плывут от
импорт-настроек и .meta-чурна, не влияющих на физику, и ломали бы капсулу
пере-импортом без изменения поведения. Формат: SHA-256 по вершинам и
треугольникам **всех субмешей в фиксированном порядке**, float — тот же
`"R"` invariant-формат, что и в существующих hash-строках захвата.
Адъюдикация 2026-08-04, вопрос №10: покрытие треугольников ВСЕХ субмешей —
ратифицированное свойство contentHash и **закрепляется отдельным тестом**
(меш с ≥2 субмешами: изменение треугольников любого субмеша меняет хэш).
Прямое следствие: геометрия обязана быть читаемой **в захватной точке**
(edit mode — Поправка 2026-08-04; эмпирически там она читаема и при
выключенном Read/Write); нечитаемая в захватной точке геометрия =
fail-closed со своей отдельной причиной (см. таблицу отказов).

**Механизм резолва (Адъюдикация 2026-08-04, вопрос №3): НИКАКОГО
`#if UNITY_EDITOR` внутри Core.** Директива заставила бы `BugCam.Core` вести
себя по-разному в редакторе и в player-сборке — ровно то, что подрывает
заявление о воспроизводимости, и это нельзя протестировать. Решение —
инжектируемый провайдер: интерфейс меш-резолва живёт в Core, реализация — в
`BugCam.Editor`; **отсутствующий провайдер = fail-closed** (строка в таблице
отказов).

## Хэш захвата — аддитивное расширение, бит-в-бит для Box/Sphere

Текущий формат (проверен по `SceneCapture.cs` `ComputeHash`, строки ~789-838):
`O|orderKey|status|reason`, `D|key|shape|pos|rot|size|mass|vel`,
`S|key|shape|pos|rot|size`; строки соединяются `\n`, SHA-256 по UTF-8,
lowercase hex; float — `"R"` invariant.

Правило расширения: **строки для Box/Sphere остаются байт-в-байт прежними.**
Только для меш-шейпов (`shape == Mesh`) строка `D|`/`S|` получает
дополнительный хвостовой сегмент:

```
|mesh:<assetGuid>:<localFileId>:<contentHash>:<convex 0|1>
```

Следствие (проверяемое): хэш захвата DominoScene
`40e466400a6fd4804a924e0376013782d40d02ffb19b14912d15d0d2bd5b6531` обязан
воспроизвестись без изменений — в сцене нет мешей, ни одна её hash-строка
не меняется.

`SimulationColliderShape` расширяется аддитивно: `Box = 0, Sphere = 1,
Mesh = 2` (существующие значения не перенумеровываются — `(int)shape` входит
в хэш).

## Manifest — секция `sceneCapture`

Текущие ключи секции не меняются и не переименовываются. Фактическая
структура (проверено по `GhostEvidenceWriter.cs`, `AppendSceneCapture`):
`captured`, `scenePath`, `captureHash`, `failureSummary` (только при отказе),
`capturedBodyCount`, `capturedStaticObjectCount`, `frozenKinematicCount`,
`excludedCount`, `kinematicFreezeWarnings[]`, `sleepingBodyWarnings[]`,
`bodyMap[]` (записи `stableId`/`hierarchyPath`/`orderKey`) и `objects[]`
(записи `hierarchyPath`/`status`/`stableId`/`reason`). Отдельного массива
статик в секции **нет** — per-object представление обоих классов несёт
`objects[]`.

Ратифицировано: записи `objects[]` для меш-шейповых объектов получают
**дополнительное** поле
`meshRef {assetGuid, localFileId, meshName, contentHash, convex}`; для
Box/Sphere-объектов поле **отсутствует** (не `null`-ится) — манифесты башни
и домино остаются байт-неизменными. Схема-версия (Адъюдикация 2026-08-04,
вопрос №8): `SchemaVersion` (= 1) **не меняется** — поля аддитивные, прецедент
подтверждён git-историей: секция `physicsSnapshot` добавлена в `fd54ab9`
(block-2.1) без изменения `SchemaVersion` (не менялся с `558d4f1`, block-1.5).
Поднимать `SchemaVersion` только при удалении или переименовании поля.

## Отсутствующий / нечитаемый меш: fail-closed (verbatim-таблица — РАТИФИЦИРОВАНА дословно)

Резолв меш-ссылки выполняется в двух точках с РАЗНОЙ глубиной проверки
(Поправка 2026-08-04 по результату эмпирической предпосылки — см. раздел
«Поправка 2026-08-04» ниже): **захватная точка** — edit mode, ДО входа в
Play Mode (в т.ч. авторитетный захват в начале рана; результат передаётся
раннеру) — полное чтение геометрии и вычисление `contentHash`;
**симуляционная точка** (инстанциирование тел в локальной PhysicsScene,
Play Mode) — геометрию НЕ читает (эмпирически нечитаема), сверяет структурный
отпечаток (vertexCount, subMeshCount, `mesh.bounds`) и null/unresolved. Отказ
в любой точке — fail-closed, никаких тихих подмен геометрии.

| Ситуация | Точка | Причина (verbatim, ратифицирована дословно) |
|---|---|---|
| MeshCollider без `sharedMesh` | захват | «MeshCollider без sharedMesh — захватывать нечего» |
| ассет по GUID не найден | захват/симуляция | «меш-ассет недоступен: <assetGuid>/<meshName> не найден в проекте» |
| суб-ассет не найден | захват/симуляция | «меш <meshName> не найден внутри ассета <assetGuid>» |
| contentHash не совпал | захват (edit mode, до входа в Play Mode) | «меш-ассет изменился с момента захвата: hash не совпадает (<ожидался> ≠ <фактический>)» |
| структурный отпечаток не совпал | симуляция | «меш-ассет изменился с момента захвата: структурный отпечаток не совпадает (vertexCount/subMeshCount/bounds: <ожидался> ≠ <фактический>)» |
| геометрия меша нечитаема (Read/Write выключен) — contentHash невычислим | захват | «геометрия меша нечитаема (Read/Write выключен): <meshName> — hash геометрии невычислим» |
| провайдер меш-резолва не инжектирован | захват/симуляция | «провайдер меш-резолва отсутствует — захват мешей недоступен в этом окружении» |
| non-convex на динамике | захват | «non-convex MeshCollider на динамическом теле не поддерживается PhysX — включите convex или это тело не захватывается» |
| нестандартные cookingOptions | захват | «нестандартные MeshCollider cookingOptions не воспроизводятся» |
| отрицательный масштаб на меше | захват | «отрицательный масштаб (зеркалирование) на MeshCollider не поддерживается в v0.1» |

Адъюдикация 2026-08-04, вопрос №9: все девять литералов таблицы ратифицированы
дословно как записаны, включая литерал отрицательного масштаба (подтверждён
решением №4). Поправка 2026-08-04, второе утверждение: изменения точек строк
«contentHash не совпал» (симуляция → захват) и «геометрия нечитаема»
(захват/симуляция → захват), а также новая строка «структурный отпечаток не
совпал» с её литералом — УТВЕРЖДЕНЫ человеком дословно; строки «ассет по GUID
не найден» и «суб-ассет не найден» сохраняют «захват/симуляция» без изменений
(резолв ассета в симуляционной точке остаётся, не читается только геометрия).

Отказ на этапе симуляции поднимается как структурная ошибка Core-результата
(правило CLAUDE.md о `readonly struct`-результатах) и доносится до бандла улик
fail-closed-документом. Код ошибки (Адъюдикация 2026-08-04, вопрос №5):
вводится отдельный новый **`SCENE_MESH_RESOLVE_FAILED`** для симуляционной
точки; захватная точка остаётся `SCENE_CAPTURE_FAILED`. Обоснование: отказ при
захвате и отказ резолва при симуляции — разные инциденты для пользователя;
второй означает, что ассет изменился или исчез ПОСЛЕ захвата, т.е. сигнализирует
сломанную капсулу улик.

**Эмпирическая предпосылка до кода (обязательная, прецедент A2/IsSleeping) —
ВЫПОЛНЕНА 2026-08-04** (три batchmode-прогона Unity `6000.3.21f1`; полные
числа — STATUS, Evidence log «2026-08-04 — Block 2.2.2: empirical readability
precondition»). Измерено: (а) edit mode — геометрия меша с выключенным
Read/Write ЧИТАЕМА (vertices/triangles/`AcquireReadOnlyMeshData` работают,
contentHash вычислим); (б) Play Mode — геометрия НЕЧИТАЕМА (vertices и
GetTriangles возвращают пустые массивы, `AcquireReadOnlyMeshData` бросает
InvalidOperationException), причём editor-канал (`AssetDatabase`) возвращает
тот же экземпляр Mesh и читаемости не добавляет; при этом vertexCount,
subMeshCount и `mesh.bounds` доступны, а MeshCollider-кукинг (non-convex
статика и convex динамика) работает. Дефолт импортёра — Read/Write ВЫКЛЮЧЕН,
т.е. предположение о типичных сторонних сценах подтверждено как дефолт.
Следствие оформлено Поправкой 2026-08-04 ниже.

## Поправка 2026-08-04 (ратифицирована человеком по результату предпосылки)

Пере-вычисление полного `contentHash` в симуляционной точке эмпирически
невозможно для типичных (Read/Write выключен) мешей. Ратифицировано:

1. **Авторитетный захват геометрии и полный `contentHash` переносятся в
   edit-mode-точку ДО входа в Play Mode**; результат захвата передаётся
   раннеру. Захватная точка остаётся fail-closed по всем прежним правилам
   (нечитаемая в edit mode геометрия = fail-closed по своей строке таблицы).
2. **Симуляционная точка геометрию не читает.** Вместо этого она сверяет
   **структурный отпечаток**: `vertexCount`, `subMeshCount`, `mesh.bounds` —
   все три эмпирически доступны в Play Mode — плюс проверка
   null/неразрешённого меша. **Сравнение отпечатка — бит-в-бит по всем трём
   компонентам** (утверждено 2026-08-04): `vertexCount`, `subMeshCount` и
   каждый float `mesh.bounds` (center.xyz, extents.xyz) сравниваются на
   точное равенство, БЕЗ допуска — обе стороны читают один и тот же ассет
   без какой-либо арифметики, поэтому любое расхождение вообще — реальное
   расхождение и fail-closed. Прецедент смешанного допуска `HasShear`
   (`1e-4 · max(1, |a|, |b|)`, `SceneCapture.cs:747`) здесь **явно
   неприменим**: там сравниваются две разные матричные реконструкции одной
   трансформации, здесь — два чтения одного значения.
3. **`SCENE_MESH_RESOLVE_FAILED`** срабатывает на неразрешённый меш ИЛИ
   несовпадение структурного отпечатка (решение №5 сохраняется: это
   по-прежнему сигнал сломанной капсулы улик — ассет изменился или исчез
   после захвата).
4. **Капсула улик честно заявляет слабость симуляционной сверки.**
   Утверждённая формулировка строки капсулы (manifest/report, дословно):
   «hash геометрии проверен при захвате; пере-проверка в Play Mode
   невозможна (Read/Write выключен). Симуляционная сверка структурная
   (vertexCount, subMeshCount, bounds): она слабее захватного hash и не
   обнаруживает правок геометрии, сохраняющих топологию и габариты — сдвиг
   внутренней вершины, переиндексацию треугольников, ре-экспорт с тем же
   хуллом». Три поля НЕ подаются как эквивалент hash — слепая зона названа
   в самой строке.
5. Утверждение формулировок получено 2026-08-04: строки 1, 3, 4 предложения —
   дословно как предложены; строка 2 (новая строка таблицы) и строка 5
   (строка капсулы) — с правками человека, внесёнными в пункты 2 и 4 выше.
   Таблица отказов приведена к утверждённой редакции (см. пометку под
   таблицей).
6. **Ратифицированный инвариант (2026-08-04): ни один путь запуска не входит
   в симуляцию, минуя захватную edit-mode-точку.** Раннер, запущенный без
   предшествующего edit-mode-захвата (полная геометрия + contentHash,
   переданные раннеру), НЕ продолжает работу на одной структурной сверке —
   это fail-closed с `SCENE_MESH_RESOLVE_FAILED`, поднятый как структурная
   ошибка Core-результата и донесённый fail-closed-документом улик;
   отдельного UI-литерала таблица per-object-причин для этого run-level
   отказа не вводит. Кого инвариант ограничивает (символы):
   `GhostEvidencePlayModeHost.TryStartTowerSearch(GhostSearchEntry, source,
   out reject)` — единственный публичный вход поиска (окно и меню оба идут
   через него; пин маршрута — `GhostEvidenceTests.cs`) — обязан выполнить
   авторитетный захват ДО того, как хост переключит `isPlaying`; scene-ветка
   корутины раннера хоста (сегодня по A2 захватывает «в начале рана»)
   потребляет переданный захват вместо пере-захвата в Play Mode;
   симуляционная сторона — `SimulationHarness.Run`/`CreateBody` (ветка Mesh)
   и `EpsilonSearchRunner.StaticColliders` — получает меш-данные только из
   переданного захвата, и достижение её без него = `SCENE_MESH_RESOLVE_FAILED`.
7. **Два обязательных теста поправки** (входят в test-список «Поверхности
   изменений»): (а) захватный `contentHash` МЕНЯЕТСЯ при правке геометрии,
   сохраняющей топологию и габариты (сдвиг внутренней вершины при неизменных
   vertexCount/subMeshCount/bounds); (б) пин известного ограничения —
   структурный отпечаток при той же правке НЕ меняется: тест документирует
   слепую зону, а не «доказывает» её отсутствие.

## Три исхода A2: расширение без слома

Модель исходов (captured / excluded-safely / fail-closed) не меняется и
остаётся исчерпывающей. Расширения только ПЕРЕВОДЯТ два класса случаев из
fail-closed в captured:

| Случай | Сейчас (A2) | Станет (2.2.2) |
|---|---|---|
| статический MeshCollider, convex любой (все условия расширения 1) | fail-closed «неподдерживаемый контактный шейп: MeshCollider …» | **CapturedStatic** |
| динамический Rigidbody + convex MeshCollider (все условия расширения 2) | fail-closed (тот же литерал) | **CapturedDynamic** |
| ВСЁ остальное | без изменений | без изменений |

Ни один случай, который сегодня captured или excluded-safely, классификацию
не меняет. Существующий литерал «неподдерживаемый контактный шейп: <тип>
(v0.1 поддерживает Box и Sphere)» остаётся для прочих шейпов (Capsule,
Terrain, Wheel, Character), но хвост скобки обязан быть обновлён на
«(v0.1 поддерживает Box, Sphere и Mesh)» — правка литерала объявляется здесь
(не молчаливая) и **одобрена** (Адъюдикация 2026-08-04, вопрос №9); связанные
test-пины обновляются ровно на этот хвост.

Остаются отказами с причинами (без изменений, перечислено явно): joints,
ArticulationBody, non-convex меш на динамике, compound-коллайдеры (в т.ч. меш
на дочернем объекте Rigidbody), несколько контактных коллайдеров на теле,
PhysicMaterial, нестандартный damping, constraints ≠ None, не-Discrete,
ручной COM/инерция, useGravity=false, shear, невалидный размер.
**CapsuleCollider остаётся отказом** — заявляется как осознанный не-охват
блока (типичные персонажи со capsule-контроллерами не захватятся; это цена
«ровно двух расширений», не упущение).

## Поверхность изменений (карта для ревью; код — после ратификации)

- **Core:** `SimulationColliderShape.Mesh = 2`; `SimulationBodyDefinition` /
  `SimulationStaticColliderDefinition` — аддитивные поля меш-ссылки и полного
  масштаба. objectScale для меш-тел (Адъюдикация 2026-08-04, вопрос №6,
  РАТИФИЦИРОВАНО): мировой AABB меша = `mesh.bounds × |lossyScale|`;
  `objectScale` = max компонента этого AABB; канал `Size` несёт этот AABB.
  Обязательный тест: `objectScale` для Box/Sphere-тел остаётся **бит-в-бит**
  прежним — score-половина гейта закрытая адъюдикация 2026-08-03, её вход
  смещаться не должен. `SimulationHarness.CreateBody`/статики — ветка
  Mesh (`sharedMesh` + `convex` + масштаб; текущая схема «unit-примитив ×
  localScale=Size» для мешей неприменима — мешу нужен реальный масштаб);
  `SceneCapture` — ветка MeshCollider в `TryDescribeSupportedCollider` +
  меш-ссылки через инжектируемый провайдер (интерфейс в Core, реализация в
  `BugCam.Editor`; отсутствие провайдера = fail-closed — Адъюдикация
  2026-08-04, вопрос №3); структурный отказ симуляционного резолва.
- **Evidence:** manifest-писатель — поля `meshRef`; схема/коды ошибок — новый
  код (вопрос №5); отчёт захвата в окне — строки меш-ссылок.
- **Editor:** без изменения входов; `TryStartTowerSearch`/entry не трогаются.
- **Tests:** новые EditMode-пины на каждую строку таблиц исходов и отказов,
  хэш-аддитивность (Box/Sphere-строки байт-в-байт), обязательный пин
  бит-идентичности `objectScale` Box/Sphere-тел (решение №6), пин покрытия
  contentHash'ем треугольников всех субмешей (решение №10), два обязательных
  теста Поправки 2026-08-04 (contentHash меняется при топологию-сохраняющей
  правке; структурный отпечаток при ней же не меняется — документированная
  слепая зона), PlayMode-смоук на меш-тело и меш-статику в локальной
  PhysicsScene.

## Открытые вопросы — ВСЕ ЗАКРЫТЫ (адъюдикация 2026-08-04)

### Адъюдицированы 2026-08-04, первая передача (№1–№3 — решения внесены в текст выше)

1. **Статический MeshCollider с `convex == true`:** ЗАКРЫТ — захватывается
   наравне с non-convex. Флаг `convex` уже есть в формате меш-ссылки и входит
   в хэш; отказ был бы абсурден: convex hull строго проще, статика не движется.
2. **contentHash:** ЗАКРЫТ — по геометрии, не по байтам файла. Байты файла
   плывут от импорт-настроек и .meta-чурна без влияния на физику. Хэш —
   вершины и треугольники всех субмешей в фиксированном порядке, float `"R"`
   invariant как в существующих hash-строках. Следствие: геометрия обязана
   быть читаемой в захватной точке (edit mode — Поправка 2026-08-04);
   нечитаемая в захватной точке = fail-closed со своей отдельной причиной.
3. **Механизм Editor-резолва в Core:** ЗАКРЫТ — НИКАКОГО `#if UNITY_EDITOR` в
   Core (директива дала бы Core разное поведение в редакторе и player-сборке,
   что подрывает заявление о воспроизводимости и нетестируемо). Провайдер:
   интерфейс в Core, реализация в `BugCam.Editor`, отсутствие провайдера =
   fail-closed.

### Адъюдицированы 2026-08-04, повторная передача (№4–№10 — решения внесены в текст выше)

> Первое сообщение с решениями №4–№10 было потеряно при передаче; решения
> получены повторной отправкой 2026-08-04 и записаны здесь дословно по смыслу.

4. **Отрицательный масштаб (зеркалирование) на меше:** ЗАКРЫТ — fail-closed
   с причиной, БЕЗ эмпирического исследования: поведение зеркалированных
   convex hull в PhysX плохо предсказуемо, а продукт продаёт
   воспроизводимость.
5. **Код ошибки симуляционного резолва:** ЗАКРЫТ — вводится отдельный новый
   `SCENE_MESH_RESOLVE_FAILED` (захватная точка остаётся
   `SCENE_CAPTURE_FAILED`). Отказ при захвате и отказ резолва при симуляции —
   разные инциденты для пользователя: второй означает, что ассет изменился
   или исчез ПОСЛЕ захвата, т.е. сигнализирует сломанную капсулу улик.
6. **objectScale для меш-тел:** ЗАКРЫТ — РАТИФИЦИРОВАН мировой AABB
   (`mesh.bounds × |lossyScale|`), objectScale = max компонента, канал `Size`
   несёт этот AABB; обязательный тест закрепляет бит-идентичность objectScale
   для Box/Sphere-тел — score-половина гейта закрытая адъюдикация, её вход
   смещаться не должен.
7. **Выбор скачанной сцены гейта:** ЗАКРЫТ — выбор за человеком; кандидаты с
   лицензией и составом коллайдеров предлагаются после ратификации
   контракта, ассистент сцену сам не выбирает.
8. **`SchemaVersion` манифеста:** ЗАКРЫТ — не меняется: поля аддитивные,
   прецедент `physicsSnapshot` (`fd54ab9`) подтверждён; поднимать
   `SchemaVersion` только при удалении или переименовании поля.
9. **Verbatim-литералы таблицы отказов:** ЗАКРЫТ — все девять ратифицированы
   дословно как записаны, включая литерал отрицательного масштаба
   (подтверждён решением №4); объявленная правка существующего
   Box/Sphere-литерала на хвост «(v0.1 поддерживает Box, Sphere и Mesh)»
   одобрена.
10. **Субмеши:** ЗАКРЫТ — contentHash покрывает треугольники всех субмешей;
    закрепляется тестом (меш с ≥2 субмешами: изменение треугольников любого
    субмеша меняет хэш).
